# 手机远程网页：加载、连接恢复与单项启动

## 本次行为

- 大按钮「启动日常（整链）」继续发送空请求，由控制器解析电脑端 `sequential_tasks` 的顺序与启用项；兼容旧 `tasks` 配置。
- 任务清单为 MAA、MaaEnd、BetterGI 分别提供「单独启动」，请求只带对应软件。软件已启用但未加入整链时仍可单独运行；软件本身停用时不可启动。
- 清单保留 `enabled` 表示是否参与整链，新增 `can_start` 表示是否可以单独启动，兼容已有客户端。
- 请求处理中立即禁用启动按钮；运行期间禁止另起工作流。空的 `software: []` 不再意外触发整链。

## 加载与连接改进

- 有登录凭据时立即展示页面，账户信息与状态并行读取；日志和报告只在打开相应标签页后读取。
- API 请求含 15 秒超时，超时覆盖响应体读取。临时网络故障保留登录，只在认证接口返回 401 时清除凭据。
- 状态刷新合并重复请求；删除每次操作后额外四轮刷新；过期会话或早于新实时状态的响应不会覆盖当前状态。
- 页面提示连接状态，提供重新连接按钮；恢复网络、回到前台时重连并同步。后台关闭实时连接，减少闲置长连接。
- 实时流每 15 秒发送可观察心跳；超过 45 秒未收到任何事件时重建连接。10 秒状态轮询继续提供兜底；实时流不可用时也刷新当前日志／报告页。
- 隐藏的日志页不重绘，显示时以 150 毫秒间隔合并日志渲染；阅读历史日志时避免强制滚动到底部。
- Service Worker 升级为 v9，安装时统一获取新版静态资源，再以缓存优先方式加载页面，避免等待卡住的外网连接。API 不进入缓存，静态 HTTP 响应要求重新验证；仅清理本应用旧缓存。
- 服务端实时队列最多 256 条，不阻塞工作流；慢客户端队列溢出时关闭连接，由客户端重连并获取快照。流写入超时 30 秒；请求等待队列增至 64。

## 部署与实机验收

本次修改在源码工作区，未替换用户正在运行的 exe。需要同时更新桌面服务端和网页资源；只复制 web/ 不会更新 `can_start`、队列与心跳等后端逻辑。发行构建继续使用 `maagent.release.spec`。若 exe 旁存在 web/ 目录，它优先于打包内置资源，更新时必须同步。

新版本运行后，用手机联网重新打开页面，使 v9 缓存完成更新，再刷新一次。依次验收三个单项启动、整链、停止、切后台返回、Wi-Fi／移动网络切换、日志与报告。

尚未在用户手机和真实 Tailscale Funnel 链路验证，不宣称已解决所有外网连接问题。电脑休眠、桌面服务退出或 Funnel 不可达仍需单独排查；离线缓存只能显示页面，不能离线控制电脑。首次访问尚无缓存时仍依赖网络。
