# 2026-10-20 首次启动原神后 Multiple games 与 BGI 退出

用户手动关闭终末地后，首次启动原神日常出现 Multiple games 提示，随后 BGI
消失；再次启动正常。以下来自当天 Maagent、BGI 日志与 Windows Application 事件。

## 已确认时间线（北京时间）

- 13:27:21 Maagent 响应终末地停止请求，发送 F11。
- 13:27:41 启动 BGI 日常；13:27:58 点击启动原神。
- 13:28:10 启动一条龙；BGI 最后一条消息为 13:28:21 等待进入游戏主界面。
- 13:28:21 Application Error 1000：YuanShen.exe 在 ntdll.dll 中异常退出，
  异常代码 0xc0000005，PID 0x3184。
- 13:28:23 Application Error 1000：BetterGI.exe 0.66.0.0 在 coreclr.dll 中异常退出，
  异常代码 0x80131623，PID 0x930C（37644，与 BGI 第一轮日志一致）。
- 同时 .NET Runtime **1025** 明确记录 Environment.FailFast，原因：
  `A callback was made on a garbage collected delegate of type 'Vanara.PInvoke.User32!Vanara.PInvoke.User32+WinEventProc::Invoke'.`
  调用栈经过 WPF Dispatcher / GetMessageW / BetterGenshinImpact.App.Main。
- 13:28:57 Maagent 才收到停止请求，13:29:00 执行停止清理。
  因此 BGI 的首次退出早于 Maagent 的停止处理，并非任务完成判定触发关闭。
- 13:29:16 存在一次短暂 BGI 启动，13:29:21 主窗口退出。
- 13:29:23 Maagent 再次启动 BGI，13:30:42 开始一条龙第 1/8 项任务。

## 结论及边界

BGI 退出原因已定位到它的窗口事件回调：本机 .NET 日志明确指出一个已被垃圾回收
的 WinEventProc 委托仍被调用，从而触发 FailFast。不是 Maagent 主动提前关闭。
原神在此前约两秒已崩溃，其窗口退出可能触发该回调，但日志不足以证明因果。

Multiple games 弹窗的来源、终末地是否有残留进程/组件，以及原神崩溃的具体原因
尚未确定。不能将 ntdll.dll/coreclr.dll 出现在故障记录中直接归因于 DLL 损坏，
也不能在未证实时声称是某个反作弊组件冲突。

本次仅排查并保存证据，未修改游戏/BGI/系统文件或更换 .NET。
后续若复现，优先收集弹窗完整标题正文及当时游戏进程；BGI 故障记录可用于上游反馈。
